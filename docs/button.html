Button

The primary action control. One button per view carries the main action; everything else steps down from it.

Component Status: in review Last updated 2026-08-21

Overview

Use the button to trigger a single, clear action — submit, save, continue, confirm. Label it with a verb that names the action, not a generic word like "OK".

The primary variant is the strongest emphasis in the set. Reserve it for the one action you most want the user to take; pair it with lower-emphasis buttons for secondary paths.

Usage

Do's and don'ts for the primary button.

Do. Use one primary button per view for the single most important action.
Don't. Stack two primary buttons side by side — the emphasis cancels out and neither reads as the main action.
Do. Label with a specific verb that names the action, like "Save changes" or "Send invite".
Don't. Use vague labels like "OK", "Submit", or "Click here" that don't say what happens.
Do. Disable the button when the action isn't available yet, so the state is honest.
Don't. Override the fill with a raw hex — bind to color/button/primary so restyles flow through the token.
