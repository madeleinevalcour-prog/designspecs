Semantic color tokens

Four core semantic color tokens for text, surface, and accent. Use the semantic token, not the resolved value — the token is the contract, the hex behind it can change.

Status: in review Scope: core semantic tokens Last updated: 2026-08-21

Overview

These tokens name intent, not color. color/text/primary means "the primary reading text on a surface" wherever it is used, so a theme or palette change updates every consumer at once. Reference the token in design and code; treat the resolved hex as an implementation detail.

Tokens

Resolved values were not read from the source of truth — the live Figma variable connection is unavailable in this environment. Only color/accent/primary has a known value, and it is a raw hex pending rebind (see below). The other three resolved values are shown as to be confirmed rather than guessed.

color/text/secondary

color/surface/raised

color/accent/primary pending rebind

Primary accent — key actions and emphasis. Currently pointing at a raw hex, not a palette token, until the teal rebind lands.

Pending: accent rebind

Don't treat #0D9488 as the final accent value. color/accent/primary is bound to a raw hex as a stopgap and is scheduled to be rebound to the teal palette token; the resolved value will change.

Note keep consuming color/accent/primary by name. When the teal rebind lands, every consumer picks up the new value with no further change.

Usage

Do reference the semantic token — color/text/primary, color/surface/raised — in both design and code.

Don't hardcode a resolved hex in a component. A pasted value drifts the moment the token is repointed.

Do pair color/text/primary and color/text/secondary for hierarchy — primary for the main line, secondary for support.
