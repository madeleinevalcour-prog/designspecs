The repo's CLAUDE.md holds the full workflow. Claude Code reads it automatically, so start Claude Code from the repo root.
  • Use existing components. Icons, buttons, chips and every other part that exists go in as library instances. Never draw or imitate them.
  • Don't detach. If content needs to vary, the component needs a slot. Flag it rather than detaching.
  • Names come from code. Component, property, layer and value names match the code. Property names are the code inputs in lowercase kebab, e.g. state=hover, size=small.
  • Bind everything. Fills, strokes, spacing and radius bind to variables; text uses text styles. If no token fits, note it as missing. Don't use a raw value.
  • Ignore hidden layers when reading or documenting a Figma file.
  • Don't invent specs. If a value or behavior isn't decided, write it as a To do.
  • Every component ships with a doc page. The component, its showcase route and its doc page go in the same change.

Do the steps in this order. Each one builds on the one before.

1–2. Build in Figma

  • Rebuilding a Novo component: use the Existing template. Give Claude the production page or the novo-elements GitHub folder as the source.
  • Net-new component: use the New template and fill in Why this component (product area and reason). The source is an HTML prototype or a base you built by hand.
  • Both templates sit under the Tracking System page in Component Migration. Claude shows a plan before it builds; check names and properties there.

3–4. Tokens and annotation

  • Component tokens alias what the component is already bound to, so nothing changes visually.
  • Annotation needs a section. The template already is one.

5. Export variables

  1. Re-export both collections from Figma with Variables Pro.
  2. Replace tokens/subatomic.json and tokens/component-migration.json.
  3. Run npm run tokens, then npm run check. Check lists any CSS variable a rename broke.
The token CSS and the prototypes' index.html files are generated. Change the source and rebuild.

6. Port to ats-ui

In the same change:

  • The component in components/projects/ats-ui/src/lib/<name>/, exported in public-api.ts.
  • A showcase route in components/projects/showcase/src/app/pages/<name>/ with an embed mode (query params), registered in app.routes.ts and the home list.

7. Doc page

  • Pages go in docs-site/docs/components/; Amplify components go in docs-site/docs/amplify/components/.
  • Examples are live <doc-example> embeds of the showcase route, never screenshots. Each one gets a figma="…" link to the node it shows.
  • Add the page to the SITE list in docs-site/assets/docs.js. The nav, search and cards are built from it.
  • Then add the docs link to the Overview note on the Figma page.
  • Start from a sample page in Component Migration (Find Results, Candidate Record, Candidate List) rather than a blank frame.
  • Build only from library instances. If a screen needs something the library can't do without detaching, flag it as a library gap.
  • With Claude, the Figma plugin's figma-generate-design skill builds screens from the library.

Repo

  1. Work on a branch, not on main.
  2. Push the branch and open a pull request. Vercel builds a preview deploy, behind the same sign-in as the site.
  3. Madeleine reviews the preview and merges. Merging to main deploys the site.
The deploy runs npm run check first. A broken token reference fails the build, and the last good deploy stays live.
