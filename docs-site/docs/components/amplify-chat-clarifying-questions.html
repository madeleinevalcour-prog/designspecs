When a request is ambiguous, Amplify asks up to 3 short questions in a card directly above the chat input, one at a time, with 2–4 tappable options each. It gets the one or two details that change the result (which job order, how far, which candidates), then runs.

The rules are in Chat interface patterns. That page wins where the two differ.

  • All answers post together as one user message, as label and value pairs: the user bubble’s clarifying answers state. Each question’s short label (“Job order”) names its row, and a chosen record shows as an entity link. Amplify’s reply names the record and filters it used.
  • The chosen record joins the context row as a removable chip, so follow-ups don’t ask again.
  • For record questions, typed text is matched against record IDs and titles. If nothing matches, show an inline message instead of guessing.
  • Ask when the answer changes the result (two job orders match, a search needs a radius) or when a wrong guess would waste a long run.
  • Don’t ask when the open record, an @-mention or a context chip already answers it; assume it and say so.
  • Don’t use the card before writes, outbound messages or bulk runs. Use an action preview or an editable plan.
Ask one round: at most 3 questions, one at a time, 2–4 options each. Guess between matching records. Ask with record options. Put the recommended option first and say where it came from: “from JO-4821”, “your access”. Signal selection with color alone. Key border and label weight change together. Keep Skip and Something else on every question, so the recruiter is never forced into an option. Use the card for confirmations or long-run plans.
  • Question: one short sentence in recruiter language: “Which job order?”, “How far from Boston should Amplify look?”
  • Options: 2–5 words, parallel structure, no trailing punctuation.
  • Recommended note: “Recommended ·” then the reason or source: “Recommended · you own it”, “Recommended · from ● JO-4821”.
  • Help text only when it changes the decision, usually data scope: “Amplify only searches records you can access.”
  • No filler openers, no “Amplify determined”, no questions that only confirm what the recruiter said.

  • The options are a role="radiogroup" labelled by the question and described by the help text. Each option is a native button with role="radio", aria-checked when selected and aria-keyshortcuts for its number.
  • Roving tabindex: one option is in the tab order; ↑ ↓ move between them.
  • The key is decorative (aria-hidden); the option announces the shortcut.
  • The step count (“2 of 3”) is aria-live="polite", so it’s announced when the question changes.
  • Buttons are named “Previous question”, “Next question”, “Dismiss questions” and “Submit answer”. The Something else field is named by its placeholder.
  • Selection shows through key border, key color and label weight together, never color alone (WCAG 1.4.1). Keyboard focus uses the active state and the focus ring.
