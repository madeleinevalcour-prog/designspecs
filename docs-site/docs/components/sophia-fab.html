Sophia FAB opens the Sophia support chatbot. It’s a round blue button that floats over the page and always sits on one of a fixed set of spots.

Three placement options are under review. Each defines its own spots and size. People drag the button to move it; it snaps to the nearest spot.

In the examples, the gray column is a stand-in for the bowling alley. Its darker blocks mark what the bowling alley is showing (nav, open tabs, foot).

Screen spots sit 24px from the stage edges in every option.

A · Inside the bowling alley

The bowling alley spots are centered in the bowling alley and move with it when it opens or closes. The top spot docks below the open tabs and the bottom spot docks above the bowling alley foot, keeping 16px clear of every bowling alley item, so the button never covers them.

B · Screen edges only

No spot is tied to the bowling alley, so opening, closing or hovering the bowling alley has no effect on the button.

C · Outside the bowling alley

The two left spots park 8px outside the bowling alley’s edge: the top one level with right-middle, the bottom one 24px from the bottom. They follow the committed bowling alley state only. A hover-peek leaves them in place and the expanding bowling alley covers the button; pinning the bowling alley open shifts them right with it.
  • Press and drag. After 4px of movement the button lifts (scales to 110%, darker blue, extra shadow) and follows the pointer, and a dashed ring appears on every spot of the current option.
  • The ring nearest the pointer fills light blue. Release to snap to it with the .18s ease the bowling alley uses.
  • A press without real movement doesn’t move the button; it counts as a click.
  • From the keyboard, focus the button and use the arrow keys to step to the nearest spot in that direction.

  • It’s a native <button>, so it’s focusable and Enter / Space activate it.
  • The icon is decorative. The button’s name comes from aria-label, “Sophia — drag to move” by default; set label to override it.

The component lives in the ats-ui Angular library. Put it inside the positioned page stage: it fills that container as a click-through layer and positions the button within it. Pass the bowling alley’s geometry in; the component doesn’t look at the bowling alley itself.

<div class="stage" style="position: relative"> <app-bowling-alley /> <ats-sophia-fab placement="A" [(spot)]="sophiaSpot" [bowlingAlleyWidth]="bowlingAlleyOpen ? 258 : 64" [bowlingAlleyZones]="bowlingAlleyZones" (activate)="openSophia()" (positionChange)="onSophiaMoved($event)" /> </div>

The prototype remembered each option’s spot in local storage. The component doesn’t persist anything: store spot yourself if you need it.

 A, B and C are open options from the prototype; no option has been picked. The button uses the utility-blue primitives directly. There’s no Sophia or matching Tier-2 / Tier-3 background token, and the Button fab tokens resolve to a darker ramp (600 / 700). Options B and C use the 56px Material FAB size. There’s no 56px spacing token. The prototype’s button has no click action. The component exposes activate; opening the chat is up to the host. Arrow-key repositioning is new in this port; the prototype only supported dragging.
