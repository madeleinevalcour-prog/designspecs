The record-list components: a header with search, filters and a view switch, over a list that shows as a table or as cards.

Six components make up the list. Toggle and AdvancedSearch also work on their own. The list comes in two variants: Classic (header option 2) and Modern (header option 4).

Toggle picks one option from two or more. It's a pill container of segments, and each segment is a dialogue Button with a pill radius. The selected segment shows the dialogue Button's active state: a light blue fill and an inset shadow. The others stay transparent until hovered.

Segments show text or an icon only.

ListHeader sits at the top of the list and stays pinned while the list scrolls. It has three rows: a toolbar (entity avatar, title, record icon buttons, the Bullhorn / Job Boards Toggle), AdvancedSearch, and a filter bar (secondary-Button filter chips, and the list / cards view Toggle).

Classic keeps a constant elevation. Modern starts flat and transparent. In card view, once content scrolls more than 4px under it, it turns translucent white with a 2px background blur and gains elevation.

ListDataTable shows records as rows. Columns are a fixed 240px, so the table grows wider than the page and scrolls sideways inside its container. The header row stays pinned on vertical scroll. Each column header has sort and filter icons. Each row starts with a checkbox and a preview icon. Body rows alternate white and a muted backdrop.

ListDataTableContainer holds the list and shows the table or the cards, per the view. In list view it's the scroll region: columns scroll sideways, rows scroll down, and the table's header row stays pinned. In card view it grows with its content and the page scrolls under the header.

  • Toggle is a role="group" with an accessible name. Each segment is a native button with aria-pressed. Icon-only segments get an aria-label ("List view", "Card view").
  • The header's record icon buttons have an aria-label each: Columns, Favorite, Refresh, Close.
  • AdvancedSearch's field has an accessible name ("AI search" by default). The bar shows a focus border while the field has focus.
  • ListDataTable uses table / row / columnheader / cell roles. Its checkboxes are native, labelled "Select all" and "Select row".

The components live in the ats-ui Angular library. Put the header and container in a flex column with a fixed height. In list view that column shouldn't scroll (the container does). In card view it should.

Toggle and AdvancedSearch use a 0 4 4 drop shadow at charcoal 8%, and cards a 0 4 4 box shadow. No elevation style matches (level 1 is 0 2 4 at 4%). The list title is 700 with -0.5px tracking in Figma; the typography/title/default token is 600 with 0 tracking. The code keeps the Figma values. Cards and the Modern container use 8px; card/border/radius/default is 16px. The 240px column width, the 2px header blur and the 40% white Modern container fill have no semantic tokens. The Favorite icon (star-o) wasn't in the icon set; it was added from the List Variations file.
