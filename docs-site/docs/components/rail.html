The rail is the main navigation. It holds the app openers (Find, Menu, Add, Amplify), the open record tabs and the utility links, and it expands from a 64px icon strip to a 258px panel.

It ships as a group: the rail itself, its parts (main tabs, record tabs divider, entity tabs), the overlays it opens, the Top Bar header, and the Amplify chat panel that docks on the right. A shell component lays them out and holds the shared state.

The rail has three states. Collapsed shows icons only. Hover expands it over the page without moving the content. Open expands it and pushes the content right.

StateEnters whenLeaves when
CollapsedDefault; the pointer leaves a hovered rail; the toggle closes an open railPointer rests on the rail for 600ms (→ hover); toggle or ⌘/Ctrl+B (→ open)
HoverPointer rests on the collapsed rail for 600msPointer leaves the rail and any open overlay for 200ms, and no overlay is open

Labels, the wordmark, the collapse toggle and the Parse Resume uploader show only when expanded. Tabs stay 32px tall in every state, so nothing jumps when the rail opens.

The prototype carries three ways to draw the hover state. Pick one with the hover input.

Find sits on top. Each opener shows a “next” chevron on hover and while its overlay is open; the open opener also takes the active background.

Overlays stay inside the layout: one that would run off the bottom is pulled up to sit 8px from the edge.

Option 1 (default): clicking Find opens the rail, swaps the Find tab for an inline search input and lists “Recently Viewed” below it at the same width. Closing it puts the Find tab back and restores the previous rail state. Option 2: Find opens a 600px overlay with its own search. Both filter the results as you type.

Each open record gets a tab with its entity chip (color/entity/<type>) and label. Click to make it active. When the rail is expanded, hovering a tab shows pin and close; a pinned tab keeps its pin visible. Drag a tab to reorder: a 2px line marks where it will land.

Hover the divider above the tabs (expanded only) to show Clear All, which closes every record tab. Hovering the pin shows a tooltip: “Pin”, or “Remove pin” on a pinned tab.

The search input is a pill with a 12px search icon. It turns subtle gray on hover; when active or focused it also takes the color/entity/candidate border and shows a close button. The list item is a result row: entity chip, title in color/text/link, then wrapping meta fields.

In the Top Bar layout, Find, Amplify and the user move out of the rail into a header above the content. Focusing the header search opens Fast Find directly below it at the same width. Amplify toggles the panel; the user opens the user menu below the avatar.

Amplify docks on the right at 420px and the page contracts to fit; it slides in by animating its width. The rail Amplify tab and the header Amplify button both toggle it; its close button shuts it. It holds a header, the thread (user message, reply, result cards, reactions) and the composer (context chips and input).
  • Hover intent: the rail waits 600ms before expanding, so passing near the edge doesn’t peek it open. It waits 200ms before collapsing, so a brief slip off doesn’t snap it shut.
  • An open overlay holds the hover state until it is dismissed.
  • One overlay at a time. Clicking the same opener again closes it; clicking another opener swaps it.
  • Clicking outside the overlay closes it (openers and the search fields don’t count as outside). If the rail was only hovered and the pointer is off it, the rail collapses too.
  • Escape closes the open overlay. ⌘/Ctrl+B toggles the rail open or collapsed.
  • The close button in a search closes its overlay and collapses a hovered rail.
  • Selecting overlay rows doesn’t navigate yet; RailShell emits overlaySelect so a page can act on it.
  • The rail is a navigation landmark (“Main navigation”); the header is a banner and Amplify a complementary region.
  • Every control is a native button. Icon-only controls carry an aria-label; openers expose aria-expanded, the Amplify tab aria-pressed.
  • Entity tabs are focusable (Enter or Space activates); pin and close appear while a tab has focus. The active tab has aria-current="page".
  • The pin tooltip also shows on keyboard focus. A closed Amplify panel is inert, so its controls are skipped.
  • Drag to reorder is pointer-only; there is no keyboard reorder yet.
