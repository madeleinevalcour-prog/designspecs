The chat block is one full Amplify reply: identity, the body, sources, follow-ups and message controls, always in that order, so replies are predictable to scan and the answer comes first. The user turn places the recruiter’s message in the same column.

The rules are in Chat interface patterns. That page wins where the two differ.

The body is projected: answer, headings, lists, evidence and blocks are the other Amplify chat components, placed in order. Everything, prose included, uses the full chat column (800 max).

  • No retry control and no feedback request in prose.
  • Stop is not a reply control. It lives in the chat input, next to Send, while the reply generates.

While a reply generates, the block shows only the status line: the Amplify icon and the current step in body/sm, color/text/secondary. Identity, body, footer and controls are hidden until the reply arrives, then the status line is replaced.

  • Name the step: “Searching open jobs…”, then “Ranking 14 job orders…”. Never “Amplify is thinking…”.
  • Never link blue: blue means clickable.
  • Stop shows in the chat input while this state is on.

A full-width row in the chat column that right-aligns the user bubble. The bubble hugs its text up to 440, then wraps. Turns sit spacing/gap/xlg (32) apart; that spacing belongs to the conversation column, not the row.

Messages, tables and the composer share the same edges, so the conversation reads as one column. Keep paragraphs short so full-width lines stay readable.

 Answer in the first line, in one sentence. If Amplify can’t help, say so there with the cause and a fix. Open with a filler line or a heading. Offer 2–3 follow-up chips for next steps. Ask “Want me to…?” or request feedback in prose. Show the sources row when the answer uses records. Show sources for clarifying questions, product help or “nothing found” replies. Let prose use the full 800 column, the same as tables and cards. Put Stop or a retry control in the reply.

The smallest reply is identity, a one-sentence answer and the controls. Add the rest only when the content needs it.
