The expanded, standalone Amplify chat: everything to the right of the Bowling Alley. A valid entry point to a workflow, not just an overflow view of the dock. It is also the prototyping shell: you supply the turns, it owns the header, the input and the layout.

Every example on this page is live: type a message and send, press Stop while a reply generates. The rules are in Surfaces and behavior, Chat input behavior and Spacing and layout. That page wins where the two differ.

The page header: the Amplify icon container (lg) and the title (title/default, “Amplify”), a Close button on the right, and a row of tabs below: Chat · Overview · Meetings · Audits. The record header isn’t reused; its toolbar, field row and More / Layout buttons are record-specific.

  • Tabs use the tab tokens; the active tab has the indicator and aria-current="page". An empty tab list hides the row.
  • Close is optional (closable).

Three states, decided by the turns you project: empty until there is a user turn or an Amplify reply.

StateLayout
Starting pointThe greeting (“Hi Chloe, how can I help you today?”) and the input in the upper middle of the page: 750 wide, 200 below the header (less on short windows). Buttons show their labels. No context row
Short conversationThe turns fit, so they are top-aligned in the 800px column and the input sits at the bottom of the page
Long conversationThe turns overflow, so the conversation is bottom-anchored: the newest reply sits just above the input and older turns scroll up behind the header
  • First send: the input moves from the starting point to the bottom of the page (a short slide; reduced motion skips it) and keeps focus, so the recruiter can keep typing.
  • Icon-only buttons once the conversation starts. Add File, Add Tools and Prompt Library show labels only at the starting point; under a conversation they are icons, the same as docked chat, so the input stays compact. Their accessible names keep the labels.
  • Context row: appears in the bottom input once the conversation starts, for example the Prospect source chip with the Amplify icon. A clarifying-questions round replaces it while open.
  • Generating: Stop shows in the input next to Send; Send stays disabled until the reply finishes or is stopped.
  • Auto-scroll: the view follows new turns only if the recruiter is at the bottom. Sending jumps to the latest.
  • Tabs switch the active tab and report it; what each tab shows is up to the page.

Use the full-page chat to prototype an Amplify flow in Angular. The shell handles the starting point, the move to the bottom, the input, scrolling and Stop. You keep the turns in a plain array, render them with @for, and push to it on send.

The live example answers in the format you ask for, so you can show each component on request: “Show candidates in cards” (entity-record cards), “Show Prospect contacts in cards” (prospect-contact cards), “Show me the results in a list”, “…in a table”, “Ask me clarifying questions”, “Draft an intro email”, “Give me a Boolean search string”. The Demo prompts button lists them; anything else cycles through the reply types. In code, the intents are a short keyword list (INTENTS in the showcase’s full-page-data.ts) you can extend for your own prototype. Like the ATS, the prototype always fits the browser window: the Bowling Alley shell is 100% of the window height, so the Bowling Alley is never cut off, the conversation scrolls inside the page and the chat input stays at the bottom of the screen. Don’t give the page a fixed height; put the shell at the top level of the page. Inside a sized container (like the examples on this page), set height: 100% on the shell instead. <ats-amplify-chat-full-page title="Amplify" greetingName="Chloe" [context]="['Prospect']" [generating]="busy()" (send)="ask($event)" (stop)="cancel()"> @for (turn of turns(); track turn.id) { @if (turn.user) { <ats-amplify-chat-user-turn> <ats-amplify-chat-user-bubble>{{ turn.text }}</ats-amplify-chat-user-bubble> </ats-amplify-chat-user-turn> } @else if (turn.thinking) { <ats-amplify-chat-chat-block status="Thinking…" /> } @else { <ats-amplify-chat-chat-block><ats-amplify-chat-text>{{ turn.text }}</ats-amplify-chat-text></ats-amplify-chat-chat-block> } } </ats-amplify-chat-full-page> ask(text: string) { this.turns.update((t) => [...t, { id: ++this.id, user: true, text }]); … }
  1. Start with an empty array: the page shows the starting point.
  2. On send, push the user turn and a thinking turn, and set generating. The input moves to the bottom on its own.
  3. When the reply is ready, replace the thinking turn with the reply (any reply components: text, lists, data table, cards, draft block) and clear generating.
  4. On stop, end the reply early.
  5. To show a clarifying round, pass questions; listen for completed and turn the answers into the next user turn.

The showcase route amplify-chat-full-page is a working example: it rotates canned replies through a data table with selection, prose with a numbered list, chat cards, a clarifying-questions round and a draft block. Pass state to force a state when your turns aren’t user turns or chat blocks.

 Use full-page chat as a starting point for a workflow, then hand the recruiter into a record or list. Treat it as an overflow view of the dock with different content. Both are one assistant with one conversation. Keep messages, tables and the input on the same 800px column edges. Widen tables or cards past the column, or show labeled input buttons under a conversation. Prototype with real reply components inside the shell. Rebuild the header, input or scrolling in a prototype, or use screenshots for replies.
