Two containers for text Amplify writes for the recruiter to use. The draft block holds text to edit before using it: an email, a note, a job description. The literal value block holds text to copy exactly as written: a Boolean search string, a field value, a short template. Both fill the chat column.

The rules for when to use each are in Chat interface patterns. That page wins where the two differ.

The value renders unchanged in body/default color/text/body: no smart quotes, no markdown, no changes to operators or parentheses. Curly quotes break Boolean strings. The tonal block shows where the exact text starts and ends.

hoverBorder chip/color/border/default/hover and the copy action at the right (Icon button no container, theme=secondary, copy icon). Also shown while focus is inside the block and just after a copy
  • Copy takes the exact string and nothing else, then shows a check for 1.5 seconds.
  • Long values wrap inside the block. Wrapping is visual only: copy adds no line breaks.
  • The copy action keeps its slot at rest, so the value doesn’t reflow on hover.
  • For a short value inside a sentence (JOB-10482), use inline code. It has no copy action.
  • Both blocks copy with the clipboard API. If the browser blocks it, nothing changes and no success state shows.
  • Draft block: Copy, Edit and Use draft are normal buttons in tab order. Use draft passes the body text to the host.
  • Literal value block: the copy button stays in the tab order while hidden. Tabbing to it reveals it and the hover border; Enter or Space copies.
 Put full emails, notes and JDs in a draft block, because the recruiter edits them. Put a draft email in a literal value block, or a Boolean string in a draft block. Show the subject row only for drafts that have a subject. Send, save or insert a draft without the recruiter choosing an action. Render literal values exactly as the model wrote them. Apply smart quotes, markdown or hard line breaks to a literal value.
  • Drafts use plain recruiting language, with no internal or model terms, and no emoji or exclamation marks.
  • A literal value block holds only the value. Put any explanation in the paragraph before it.
  • Short templates with placeholders are literal values; the recruiter pastes them and fills the placeholders.

  • The draft block is a role="group" named by its subject, or “Draft” when there is none.
  • Both blocks announce a successful copy through a polite live region: “Draft copied” and “Copied”.
  • The literal value copy button is named “Copy” by default; set copyLabel to say what it copies, such as “Copy Boolean string”. After a copy its name is “Copied”.
  • The hidden copy button uses opacity, not visibility, so it stays reachable by keyboard and appears on focus.

Both fill their parent’s width. The renderer maps a fenced code block to the literal value block.
  • Chat interface patterns: draft block, literal value block, choosing a format, spacing and layout.
  • Text: the paragraph that introduces a block.
  • Button and Icon button no container: the actions inside the blocks.
 The literal value copy action appears on hover and on keyboard focus. Touch users have neither; decide whether it stays visible on touch. Modern UI has no monospace text style, so literal values render in body/default. Monospace would separate similar characters in Boolean strings; raise it with the Modern UI system owners.
