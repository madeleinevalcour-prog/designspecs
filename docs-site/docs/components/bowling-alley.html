The bowling alley is the main navigation. It holds the openers (Find, Menu, Add, Amplify), the open record tabs and the footer (Parse Resume, Help, Privacy, user). It expands from a 64px icon strip to a 258px panel.

A shell component lays it out next to the page content and renders its overlays. The overlays and tabs are composed from their own components: Menu (the Menu, Add and user menus are its variants, built from Menu Header, Menu Item, Menu Option and Menu Edit, the Edit Menu, with Switch and Check List), Search Input (Fast Find and the Menu’s Filter), Novo List (each Fast Find result is a Novo List item) and Icon Container (the icons in the Menu, the Add menu and the entity tabs).

Collapsed shows icons only. Hover expands the bowling alley as a floating card over the page, without moving the content. Open expands it and pushes the content right.

Labels, the wordmark, the collapse toggle and Parse Resume show only when expanded. The toggle shows expand-right in the hover state (the floating card) and contract-left when pinned open.

Clicking Find turns the Find tab into a search input and widens the bowling alley to 556px, as an overlay on the page: the page content doesn’t move. The results open 4px below the search, at its width. A scrim covers the page under them.

With an empty search the results list “Recently Viewed” records. Typing filters them and shows a View All action at the top. Closing the search (its close button, Escape or a click outside) puts the Find tab back and returns the bowling alley to its previous width.

Each overlay opens 8px right of the tab that opened it. While one is open, a scrim (color/background/overlay) covers the page under the bowling alley and the overlay.

An overlay that would run off the bottom is pulled up to sit 8px from the edge. Amplify is a tab, not an overlay: the shell emits amplifyClick and the page opens its Amplify panel.

Each open record gets a tab with its entity icon (an icon container, size sm, in color/entity/<type>) and label. Click to make it active. When expanded, hovering a tab shows pin and close; a pinned tab keeps its pin visible. Drag a tab to reorder: a 2px line marks where it will land.

Hover the divider above the tabs (expanded only) to show Clear All, which closes every record tab. Hovering the pin shows a tooltip: “Pin”, or “Remove pin” on a pinned tab.
  • Hover intent: the bowling alley waits 600ms before expanding, and 200ms before collapsing.
  • An open overlay or Fast Find holds the hover state until it is dismissed.
  • One overlay at a time. Clicking the same opener again closes it; another opener swaps it.
  • A click outside (on the scrim or the page) closes the overlay or Fast Find. If the bowling alley was only hovered and the pointer is off it, it collapses too.
  • Escape closes the open overlay or Fast Find. ⌘/Ctrl+B toggles open or collapsed.
  • Menu: Add/Remove switches to the Edit Menu; Done switches back. Unchecking an app there hides it from the Menu; Grouped shows a folder as its own labelled section.
  • Menu reorder: drag a tile onto another. The dragged tile shows the menu-item drag state and a 2px color/border/focus bar marks where it lands (left or right half of the target). Tiles move within their section. The order is kept in the controller (menuOrder) while the page is open.
  • Rows don’t navigate yet; the shell emits overlaySelect so a page can act on them.
  • The bowling alley is a navigation landmark (“Main navigation”); each overlay is a labelled dialog.
  • Every control is a native button. Icon-only controls carry an aria-label; openers expose aria-expanded.
  • Entity tabs are focusable (Enter or Space activates); pin and close appear while a tab has focus. The active tab has aria-current="page".
  • Show Chat Button is a native checkbox with role="switch"; the chat positions are a radio group.
  • Menu tiles: focus a tile and press Alt+Arrow keys to move it (Left/Right one place, Up/Down one row). Each tile describes the shortcut, and a live region announces the new position.
  • Entity tabs: drag to reorder is pointer-only; there is no keyboard reorder for tabs yet.
