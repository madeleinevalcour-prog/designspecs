Amplify chat beside or over the current page. One assistant, two presentations of the same conversation: a docked panel on the right (the default) and a pop-over window. The recruiter switches between them in the header without losing the conversation or its context.

Inside both sits the conversation layout: the turns in a scrolling column with the chat input pinned at the bottom. The full-page chat uses the same layout (see Full-page chat). The rules are in Surfaces and behavior and Spacing and layout. That page wins where the two differ.

The default presentation. A 420px panel on the right that stays with the recruiter across records and pages. It is the last item in a flex row with the page content, so the page contracts beside it instead of sitting under it. It slides in from the right when opened.

  • Background color/background/muted, a 1px modal border on its left edge and general/level 3 - right. The shadow falls on the left only, never over the app chrome.
  • Escape doesn’t close it. The docked panel is persistent; only Close does.
  • While closed it is removed from the tab order and hidden from assistive tech.

The same chat as a floating window over the page. There is no scrim, so the page underneath stays usable. It opens at 726 × 994 in the bottom-right corner, 24 from the viewport edges, and shrinks to fit smaller windows.

The slide-out title header: the Amplify mark and “Amplify” (title/medium), then two small icon buttons. Header background, padding and gap come from the card header tokens, with a bottom border and general/level 1.

A new docked chat opens with a greeting from Amplify in the chat column: “Hi Chloe, how can I help you today?”. It is an ordinary Amplify reply with no actions, so the conversation reads the same from the first turn. The input sits at the bottom as normal.

The shared chat layout: a scrolling column of turns with the chat input pinned at the bottom. The docked panel, the pop-over and full-page chat all use it.

  • Alignment: while the turns fit, they are top-aligned and the input sits at the bottom of the view. Once they overflow, the conversation is bottom-anchored: the newest content sits just above the input and older turns scroll off the top.
  • Auto-scroll: when a turn is added or grows (a thinking line becomes the reply), or the input grows, the view follows the newest content only if the recruiter was already at the bottom. If they scrolled up to read, they stay where they are.
  • Sending jumps to the latest and resumes following.

  • The chat is a role="complementary" landmark named “Amplify chat”. While closed it is inert and aria-hidden.
  • The header title is an <h2>. The icon buttons are named “Pop out” / “Dock to side” and “Close Amplify”.
  • The turns column is a role="log" region with aria-live="polite", named “Conversation”, so new replies are announced without interrupting.
  • Escape follows the innermost layer: an open menu closes first, then the pop-over.
  • Moving and resizing the pop-over are pointer-only today (see To confirm); docking it back is always one button away.
