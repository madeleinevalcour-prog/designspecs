The table Amplify uses to show 2–10 records compared on the same short fields, such as prospect contacts from a Prospect search. It sits in a card, is built from the Data Table cells, and carries its own selection and selection bar. Chat tables have no sort, filter or minimum column width.

The rules for when to use a table instead of cards or prose are in Chat interface patterns. That page wins where the two differ. For the base cells, states and measurements, see Data Table.

  • At most 4 columns in docked chat and 6 in full-page chat. The record name is always the first column.
  • At most 10 rows. With more results, the reply shows the first 10, “Showing 10 of N” in meta/default and a “Show more” chip.
  • No sort or filter controls. The table summarizes the answer; deeper work happens in the full list view.
  • Columns have no minimum width. The table scrolls sideways inside the card if it has to.
  • Row dividers only: no vertical lines. All columns are left-aligned.

 Use a table to compare 2–10 records on the same short fields: a name, date, ID, status. Use a table when each record needs a reason it was picked or several chips. Use cards. Keep to 4 columns docked and 6 full page, with the record name first. Add sort, filter or column menus, or show more than 10 rows. Show checkboxes only when the reply offers a bulk action. Build a custom markdown table style or override the table’s tokens. Show an empty value as “Not on file”, or a Reveal link for a prospect not in Bullhorn. Show one set of records as both a table and cards.
  • Header labels are Title case in the source (“Job Title”) and render uppercase.
  • Status text is exactly “Existing Contact” or “Not in Bullhorn”.
  • Reveal links read “Reveal Phone Number” and “Reveal Email”.
  • Empty values read “Not on file”, never “—”.
  • Over 10 results: “Showing 10 of N” under the table, then a “Show more” chip.
