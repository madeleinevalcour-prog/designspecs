Button triggers a single action. It comes in seven themes, three sizes and five colors, and every color is bound to a Tier-3 button token.

Pick the theme by emphasis: the strongest theme goes to the one action you most want taken, and everything else steps down from it. Pick the color only when the action carries a meaning the color names (destructive, confirming, cautionary, AI).

Themes run from most to least emphasis. Each has its own background, content, border and focus tokens.

Fab and icon buttons are square at the same heights: 32, 40 and 48px. Height, padding and gap come from button/spacing/<size>/*; text comes from the subatomic typography/button/<sm|default|lg>/* tokens.

Every theme has five states. Each state swaps the background, content and (for secondary) border tokens; nothing else moves, so the button never shifts layout.

A color that has no tokens for a theme (for example warning on standard) renders as that theme’s default color.

Text buttons take an optional leading and/or trailing icon. Fab and icon buttons take a single glyph. Icons come from the icon set and take the button’s content color, so they follow every state and color automatically.

 Use one primary button per view for the single most important action. Put two primary buttons side by side; the emphasis cancels out. Label with a verb that names the action, like “Save changes” or “Send invite”. Use vague labels like “OK”, “Submit” or “Click here”. Use negative for actions that destroy or remove something, so the risk is visible before the click. Use color for decoration. If the action doesn’t carry that meaning, keep it default.
  • It’s a native <button> (or <a> for navigation), so keyboard, forms and screen readers work without extra code.
  • Fab and icon buttons have no visible text: always give them an aria-label that names the action.
  • Focus is a 2px ring drawn inside the edge, so it’s visible without shifting layout.
  • Disabled buttons are skipped by the keyboard. If people need to discover why an action is unavailable, keep it enabled and explain instead.

The component lives in the ats-ui Angular library. It’s an attribute on a native element, so standard attributes like disabled and type work as usual.

<button ats-button theme="primary" iconLeft="add">Add candidate</button> <button ats-button theme="secondary" color="negative">Delete</button> <button ats-button theme="icon" icon="close" aria-label="Close"></button> <a ats-button theme="dialogue" href="/jobs">View jobs</a>
