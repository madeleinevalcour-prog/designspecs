Card groups one block of record content under a header with a title and actions, with an optional footer link.

The family has six parts: Card (the frame), CardActions (header buttons), CardDetailRow and CardResume (bodies), and RecordDetailsList with ValueWithLabel (a multi-column details body).
PartWhat it is
GripperDrag handle in the header’s left gutter. Shows only while the pointer is over the header, so it never shifts the title.
Header icon + titleSet by the variant; override either one. Title uses the title/small text style, capitalized.
ActionsCardActions by default; replace with your own.
BodyAny content. Rows sit edge to edge; padded bodies use the ats-card__pad class.
FooterOptional full-width “View All” button with a trailing arrow.

The variant sets the header icon and title. It doesn’t change the body; you supply that.

The header’s icon buttons: Add, Expand, Refresh, Close. Configure appears between Refresh and Close only when settings is on. Each is an ats-button (icon theme) narrowed to a 24px no-container button: transparent at rest, color/background/subtle on hover, 12px glyph in color/icon/illustration.

One label + value row for a details body. The label is uppercase in input/label/md, capped at 200px; the value uses input/value/default at medium weight. Rows are at least 40px tall, with a hairline between rows and none after the last.

KindRenders
textPlain value (default)
multiStacked values; the row top-aligns
selectValue with a trailing 12px chevron in color/icon/subtle
linkLink-colored value, optional 8px leading dot (for example an entity color)

The resume body: name, contact line, then titled sections. It currently renders fixed sample content from the prototype; it takes no inputs. See the resume example under Variants.

A grid of ValueWithLabel blocks, three columns by default. Use it inside a padded details body for the “columns” layout.

An uppercase label (input/label/sm) stacked over a value. The default value uses meta/default; plain switches to input/value/default for dates and yes/no. An optional 12px icon follows the value. Long labels and values truncate with an ellipsis.
  • Header actions and the footer are native buttons, so they’re reachable by keyboard and show the ats-button focus ring.
  • Header actions have no visible text; each carries an aria-label (Add, Expand, Refresh, Configure, Close).
  • Icons are decorative (aria-hidden); the title and labels carry the meaning.
  • The gripper is visual only. There’s no keyboard reordering yet.

All six components are standalone exports of the ats-ui Angular library. Card projects its body; put your own <ats-card-actions> (or any element with the cardActions attribute) inside it to replace the default actions.

<ats-card variant="details" showFooter (action)="onAction($event)" (footerClick)="viewAll()"> <ats-card-detail-row label="Location" value="Boston, MA" /> <ats-card-detail-row label="Skills" kind="multi" [values]="skills" /> <ats-card-detail-row label="Owner" kind="link" value="Chloe Davis" dot="var(--color-entity-candidate)" href="/owner/1" /> </ats-card> <ats-card variant="details" title="Record Details"> <div class="ats-card__pad"><ats-record-details-list [fields]="fields" [columns]="3" /></div> </ats-card> <ats-card variant="resume" showFooter><ats-card-resume /></ats-card>
