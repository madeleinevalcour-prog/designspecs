The prose building blocks of an Amplify chat reply: headings, paragraphs, the status line, inline record links and numbered lists. Each maps one markdown element the model outputs to one Modern UI text style, so nothing in a reply renders at a raw size or weight. Each fills its parent’s width.

The rules for when to use each, and how they combine with tables, cards and blocks, are in Chat interface patterns. That page wins where the two differ.

A heading inside a reply. Two levels; the heading text is the content.

LevelUse
section (default)Only when a reply has 3 or more parts the recruiter scans between, like “Top Priority”, “Needs Attention”, “Can Wait”. The largest style a reply can use
labelA label inside a section. Use rarely; never a second tier of structure
  • Title case, 2–5 words, no numbering, no trailing punctuation.
  • One heading level per reply. #### and deeper render as a paragraph.

Reading text in a reply. Three types.

TypeUse
paragraph (default)Plain text. The first paragraph is the answer. Several <p> children get spacing/padding/sm (8) between them
paragraph-with-linksA paragraph that names records. Each record is an inline entity link
statusThe thinking line while a reply generates: the Amplify icon (Icon/Amplify Radial) and the current step. Replaced by the reply
  • Bold (<strong> / <b>) renders body/default-medium in the same color. At most one bold phrase per paragraph.
  • Italic renders as plain text; Modern UI has no italic style.
  • The status line names the step (“Searching open jobs…”, then “Ranking 14 job orders…”), never “Amplify is thinking…”. It is never link blue, because blue means clickable.

Every Bullhorn record in a reply is a link that opens the record: a circle in the entity’s color, joined to the record name with a no-break space so the circle never sits alone at a line end. It matches the link-text component at its default size. In Figma it is drawn inside the paragraph-with-links text, because Figma can’t place a component inside a text layer.

  • The link text is the record name, not the ID. Show the ID as meta text only when it tells two records apart.
  • Punctuation follows the link directly.
  • Weight, color and the circle together carry the link, not color alone.

An ordered list: a native <ol> of list items, numbered automatically from 1, spacing/gap/xsm (4) between items. Each list item is a 16px right-aligned marker column (the list indent, spacing/padding/md) then the text, which may contain entity links and one bold phrase.

  • Use only when order means something: rank, priority or steps.
  • At least 2 items; a single item is a sentence. One idea per item, under two lines where possible.
  • Each list starts at 1. Never carry numbering across sections.
  • Nest no more than one level. If you need more, use a table or cards.
 Lead with a one-sentence answer in a paragraph. Open a reply with a heading or a filler line. Default to no headings. Add section headers only for 3 or more parts. Number headings (“1) Three CSM roles”) or use bold as a heading. Numbering belongs to lists. Bold one fact per paragraph or item: a name, count, date or status. Bold labels and values in the same line, or emphasize with ALL CAPS, underline or color. Link every record by name, with its entity-color circle, using the link component. Show a bare ID as the only reference, or rebuild the circle and restyle the link. Name the current step in the status line. Use a run of very short list fragments. Merge them into a sentence or a table row.
  • Plain recruiting language: job order, submittal, placement, pipeline. No internal or model terms.
  • Paragraphs of 2–3 sentences.
  • Hedge only where it’s true: “Amplify suggests”, “Based on 14 job orders”.
  • When Amplify can’t answer, say so in the first line, then the cause and a fix: “No open jobs found for Verizon. Check the job status filter or ask about all jobs.”
  • No emoji or exclamation marks.

  • Headers are role="heading" with aria-level 3 (section) or 4 (label), so they sit below the chat panel’s own title. Set ariaLevel to fit the host page.
  • The status line is role="status", so each step change is announced politely.
  • The entity circle is decorative (aria-hidden); the record name is the link’s accessible name. The link doesn’t rely on color alone.
  • The numbered list is a native <ol> with role="list" restored (Safari drops list semantics with list-style: none). The visible marker is aria-hidden; the list itself conveys order.
  • Emphasis comes from weight (body/default-medium), never from color alone.
