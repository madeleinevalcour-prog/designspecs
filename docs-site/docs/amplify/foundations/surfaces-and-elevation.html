Amplify chat can appear as a full page, docked beside the current page, or as a pop over, depending on the workflow and where the user starts from. All three are one assistant: they share the same conversation and context, so the user can move between them without starting over.

SurfaceWhat it isSpecs
Docked chatThe persistent panel that stays with the user across records and pages. The default presentationDocked chat → Docked panel
Full-page chatThe expanded, standalone chat. A valid entry point to a workflow, not just an overflow view of the dockFull-page chat
Pop overDocked chat as a resizable, movable window over the page, switched from the top left of the panel. Same functionality, no scrim: the page underneath stays usableDocked chat → Pop-over
  1. Context persists across navigation. The conversation and its working context (records, searches, filters, intent) carry across page changes.
  2. Chat can drive cross-page workflows, in both directions: docked chat takes the user to the next page; full-page chat can start a workflow and bring them into a record or list. Directional: interaction patterns are still being defined.
  3. Chat follows the user everywhere. Unsupported pages fall back to global chat instead of losing chat. Directional: confirm the fallback per page.
  4. History is always reachable from the dock, and a past conversation can continue in a new context.
  5. The surfaces stay aligned. Docked and full-page chat feel like one assistant (H4).

Applying this to other product areas

  • List the workflows chat should support, which cross pages, and the context each must carry (records, searches, filters, selections, intent).
  • Define entry points (docked, full page, or both), the page-to-page handoffs, and which pages fall back to global chat.
  • Confirm the experience is continuous across docked and full-page chat.
