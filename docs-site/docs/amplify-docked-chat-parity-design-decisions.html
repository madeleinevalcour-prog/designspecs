Goal

  • Give docked chat all the functionality of global (full-page) chat: starting point, prompt library, chat history and the rest.
  • Design for the future state, where one chat follows the recruiter around the ATS and moves between docked and full page without starting over (Surfaces and behavior, principles 1 and 5).

Current constraints

  • Docked chat doesn’t follow the recruiter yet. A chat is opened on a record and stays on that record.
  • The recruiter can add other records as context, but the chat still belongs to the record it was opened on.
  • Chats can be reached from chat history on any record. Opening a chat that belongs to another record takes the recruiter to that record with the chat open. For example, opening a job’s chat from chat history on a candidate goes to the job record.

Two decisions: how the recruiter opens chat history from the docked header, and what it shows. Both open as a dropdown over the chat, 4px below the button, at general/level 4. The header shows the chat’s name, or “New chat” before the first message.

Opening chat history

OptionControlStrengthsWeaknesses
A · Chat name dropdownA chevron icon button next to the chat nameTies the list to the chat it replaces. No extra header actionA chevron next to a title reads as “rename” or “more options” as often as “history” (H6). Easy to miss
B · History buttonA clock icon button in the header actions, before Pop out and CloseA familiar history control (H4). Sits with the other chat actions, so it’s found where actions areOne more icon in the header
  • It’s clearer. A clock icon is a recognized history control, so recruiters don’t have to guess what it opens (H6, recognition over recall; H4, consistency and standards).
  • It keeps the chat name as a plain title, so the header reads as one thing: which chat this is (Rams 4, understandable).

Behavior

  • Opening a chat from this record replaces the open chat in the panel.
  • Opening a chat from another record takes the recruiter to that record with the chat open.
  • Search filters as you type: chat titles, descriptions and record names.
  • Escape closes the dropdown and returns focus to the button that opened it. A click outside also closes it.
How chats with no record (for example ones started on the Amplify tab) open from docked chat. The prototype opens them in place.
  • The docked header title is the chat’s name. Before the first message it reads “New chat”.
  • The first message names the chat. The title then updates in the header and in chat history.
  • Same title style as today’s docked header (title/medium), after the Amplify mark. Global chat shows the same name in its breadcrumb, so the chat reads the same on both surfaces (H4).
How chat names are generated, and whether the recruiter can rename a chat.
  • A New chat icon button (add) sits first in the header actions. It opens the starting point on the current record.
  • It stays out of the history dropdowns, so they only list chats (Rams 10).
Whether an empty new chat is saved to chat history before the first message. The prototype only saves it once a message is sent.
  • Keeps the docked rule: the greeting is an Amplify message in the chat column and the input stays at the bottom (Docked chat, empty state).
  • Adds three starters under the greeting, specific to the open record, so the recruiter isn’t left with a blank input (AI wayfinding: specific starting points, not “ask anything”).
  • Global chat shows four starter cards at its starting point. Docked shows three compact rows, to fit the 420px panel.
The starter prompts in the prototype are placeholders. Who writes them per record type, and whether they come from the prompt library.
